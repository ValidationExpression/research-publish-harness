# Python 开发规范

## 适用范围与项目约定

1. 适用于 Python 服务、库、脚本和数据任务；必须遵循项目声明的 Python 版本、目录布局与依赖管理方式，不强制引入后端框架。
2. 格式化结果以项目已有工具和配置为准，未约定处遵循 PEP 8；禁止为风格偏好另加冲突的格式化或检查工具。

## 代码组织与架构边界

1. 按业务能力组织模块，明确 I/O 与纯计算边界，避免循环导入和导入时执行网络请求等副作用；不强制 API / Service / Repository 分层。
2. 配置与外部资源在明确入口初始化并传给使用方，优先复用项目已有封装；模块级可变状态必须明确生命周期与并发访问约束。

## 类型、命名与可读性

1. 对外函数、方法及核心边界必须添加参数与返回值类型标注；可空值和集合元素类型须明确，外部输入必须运行时校验，禁止把标注或 `cast` 当作验证。
2. 变量与函数采用 `snake_case`，类采用 `PascalCase`，模块常量采用 `UPPER_CASE`；兼容外部接口时遵循既有契约。
3. 禁止可变默认参数，按调用创建新的容器或使用工厂；避免隐藏共享状态及为压缩行数堆叠复杂推导式。

## 错误处理、并发与资源管理

1. 只捕获能够处理的具体异常，并缩小 `try` 范围；边界兜底必须记录或传播失败，禁止裸 `except` 吞错，转换异常时使用 `raise ... from ...` 保留原因。
2. 文件、锁、连接和事务优先使用 `with` / `async with`，但必须按文档确认其退出语义是否释放或归还所拥有的资源；仅管理事务的上下文（如 `sqlite3.Connection`）不等于关闭连接。无资源释放语义时，必须通过 `finally` 显式关闭或归还，或由具备该职责的外层上下文管理器完成，明确资源所有权。
3. 同步与异步边界必须明确，禁止在事件循环内直接执行阻塞 I/O 或长时间 CPU 计算；异步任务必须等待或受生命周期管理，传播取消并完成清理。

## 依赖、安全与数据访问

1. 必须使用项目现有隔离环境与锁定机制获得可复现依赖，并审查锁文件或约束文件变更；仅声明宽泛版本范围不等于锁定，禁止运行时安装未知包。
2. 外部路径必须校验允许根目录及解析后的目标；调用 `subprocess` 优先传参数列表且保持 `shell=False`，设置适用的超时并检查退出状态，禁止拼接不可信输入进入 shell。
3. 数据查询必须参数化并明确事务边界；禁止对不可信数据使用 `eval`、`exec` 或不安全反序列化，敏感配置遵循项目现有入口。

## 测试与工具链

1. 必须运行项目现有测试、格式检查和已配置的类型或静态检查，测试覆盖可观察行为、异常、边界值与资源释放；缺陷修复须补充回归用例，不强制更换测试库。
2. 若项目使用 pytest，优先以参数化用例覆盖输入组合，fixture 必须隔离并清理状态；测试不得依赖执行顺序或以内部 mock 调用替代业务结果断言。

## 条件式框架规则

1. 若项目使用 FastAPI，必须明确请求与响应模型及依赖生命周期，校验外部输入；异步路由中的阻塞工作须隔离，不能向响应泄露内部异常和敏感字段。
2. 若项目使用 Django，必须遵循应用边界，通过项目迁移机制管理模型变更；检查查询次数、事务范围与授权，使用模板和请求安全机制时不得随意绕过保护。
3. 若项目使用 Flask，必须保持应用配置、请求上下文与资源清理边界明确，按现有模式组织应用，禁止将请求状态泄漏到跨请求全局变量。
4. 若项目使用数据任务或数据处理框架，必须声明输入模式、缺失值处理和输出契约，限制批次与内存占用；随机过程需按项目要求可复现，重跑必须考虑幂等性与部分产物恢复。
